### ⚠️ 本包**没有**做到的事

**没有对原版做过任何运行时观察。** 也就是说 C 级证据**不能**用来声称"原版跑起来就是这样"。原因（都是环境限制，不是没尝试）：

1. **本机浏览器起不来** —— Chrome/Edge 在 Windows 上必须创建命名管道做 Mojo IPC，而 DSH 沙箱在两种受限模式下都禁用命名管道，Edge 直接 `FATAL: platform_channel.cc Check failed: 拒绝访问`。所以"用真浏览器加载 Ruffle 跑 SWF"这条路是死的。
2. **`archive.org` / `raw.githubusercontent.com` 在本网络区域不可达**，拿不到 Flashpoint 的完整归档。
3. **Flash 已于 2020 年 EOL**，没有官方运行时。
4. 反编译出的代码里**已经嵌着** Box2D 与 Nape 两个物理引擎的实现（`nape/*`、`Box2D/*`），其中 Box2D 整套是死代码 —— 这类"读代码才能发现"的事实本身就说明静态分析在这里是主要手段。

**因此，凡是涉及"手感"的判断（例如减速度够不够、氮气该不该自动喷），都应当以你自己跑一遍原版为准。** 本包能保证的是：**参数值和公式与反编译出的源码逐字一致**。

如果你能在有 Flash 环境（或 Ruffle 桌面版）的机器上跑原版，建议重点核对这几项：
- 按住 ↑ 时车轮是否在 2 秒内明显提速
- 松开油门后车是"滑行"还是"立刻停"（本包预测：滑行，Car1 每秒约 −40 px/s，Car3 约 −170 px/s）
- 氮气是从关卡一开始就冒火，还是要按什么键

## 1. 一句话概括手感

> 车身是一块刚体，车轮是 N 个独立刚体，每个轮子通过 **一条滑槽（只许沿悬挂轴滑动、转动自由）+ 一根弹簧** 挂在车上。
> **没有转向。** 油门 = 给前 N 个驱动轮每物理步施加恒定扭矩；刹车 = 只是把车轮角阻尼从 `wheelDamping` 切到更高的 `brakeDamping`（**没有倒车档**）；左右键 = 给**车身**施加 `±adjustTorque` 的扭矩，用来在空中调整姿态。
> 剩下就是一个油箱和一个氮气瓶。

## 3. 单位系统（**最容易搞错的地方**）

```
FGKit/Utils.as:28                  PhysicsScale = 0.1
FGKit/Physics/NapeUtils.as:21      PointToVecScaled(p) = Vec2(p.x*0.1, p.y*0.1)
FGKit/Physics/PhysicalBodyNape.as:526
    applyGlobalForce(force.x, force.y, point.x*0.1, point.y*0.1)
```

| 量 | 单位 |
|---|---|
| 形状顶点、关节锚点、`boostPoint`、坐标 | **像素**，内部 ×0.1 转成引擎单位 |
| `motorTorque`、`adjustTorque`、`boostForce` | **引擎单位**，直接使用，不再缩放 |
| 重力 | 引擎单位：**`(0, 500)`** |

> 换算：**1 引擎单位 = 10 像素**。坐标轴是 **y 向下为正**（所以重力是 `+500`）。

`ZombyHill/AppStates/LevelState.as:74` → `CreatePhysicalWorld(new Point(0, 500))`。

> 若把 1 引擎单位当成 1 米，重力就是 500 m/s²（对一辆 9 米长的车来说极强）。**移植到 Box2D 这类以米为调参基准的引擎时，要么照搬原数值，要么把整个场景按比例缩放——两者只能选一个，不要混。**

## 4. 每个物理步做什么（完整算法）

对应 `ZombyHillCommon/CarBehaviour.as:445-743 OnPhysicsStep(dt)`。已由 `src/driving.js` 实现并跑通（见 §8 的实测数据）。

```text
step(intent, dt):
  # 1) 空中调姿                       CarBehaviour.as:456-505
  if wheelsBlocked: isBoosting = false; return        # 车轮被卡死则整步跳过
  if intent.tiltLeft:  chassis.applyTorque(-adjustTorque)
  elif intent.tiltRight: chassis.applyTorque(+adjustTorque)

  # 2) 氮气                            CarBehaviour.as:507-583
  if boost > 0:
      boost = advanceNumber(boost, 0, dt)      # 线性烧完
      isBoosting = true
      f = rotate(boostForce, chassis.rotation) # 力先按车身旋转
      len = |f|; f.y *= 0.1                    # 把 Y 分量压到 10%
      f = normalize(f) * len                   # 再复原模长 ⇒ 几乎是水平推力
      chassis.applyForce(f, transformPoint(boostPoint))
  else: isBoosting = false

  # 3) 车轮：扭矩 + 阻尼                CarBehaviour.as:584-703
  fuelUsed = 0
  for i in 0..wheelCount-1:
      if i < drivingWheels and fuel > 0 and acceleratorPressed:
          wheel[i].applyTorque(motorTorque)
          fuelUsed++
      wheel[i].setAngularDamping(brakePressed ? brakeDamping : wheelDamping)

  # 4) 随速度增加的空气阻力（软限速）   CarBehaviour.as:704-722
  d = min(0.999, max(|chassis.velocity| - 1300, 0) * 0.003 + chasisDamping)
  chassis.setLinearDamping(d)

  # 5) 烧油（按被驱动轮占比归一）        CarBehaviour.as:724-742
  if fuelUsed > 0: fuel = advanceNumber(fuel, 0, dt * fuelUsed / drivingWheels)
```

辅助函数 `advanceNumber(cur, target, amount)`（`FGKit/Utils.as:983`）：朝 `target` 移动 `amount`，不越界。

**失败条件**（`CarBehaviour.as:2233`）：`IsOutOfFuelAndBoost() = (fuel <= 0 && boost <= 0)`。

**关键实现细节**：

- `motorSpeed` **不参与物理**。它只喂引擎音效曲线（`GetDesiredEngineSpeed()` / `CreateSounds()`），移植时可以直接忽略。
- 氮气**没有任何输入方法**：`m_boost` 全类只被赋值两次 —— 初始化（`:169 = boostCount`）和衰减（`:547`）。也就是说**氮气从第一帧起自动喷，一直烧到 0**。它是一份"预算"，不是按钮。这跟 `IsOutOfFuelAndBoost()` 作为失败条件是自洽的。
- `brakeForced` / `wheelsBlocked` 由游戏逻辑置位（`:2112`），分别表示"强制刹车"和"车轮卡死"。

## 5. 悬挂 / 关节结构（**移植的核心**）

`CarBehaviour.as:370-371`（`_loc3_` 是轮子的世界坐标，`_loc4_` 是只含旋转的矩阵）：

```as3
grooveJoint = CreateGrooveJoint(body, wheel,
                  wheelWorld + rot(0, -suspensionLength),   // 滑槽起点
                  wheelWorld,                               // 滑槽终点
                  wheelWorld);                              // 轮子锚点
springJoint = CreateSpringJoint(body, wheel,
                  wheelWorld + rot(0, -100),                // 锚点：轮子上方 100px
                  wheelWorld,
                  100,                                      // 自然长度 100px
                  suspensionStiffness, suspensionDamping);
```

要点：

1. **滑槽长度 = `suspensionLength`**，方向竖直，位置即轮子的名义位置；轮子可在其中滑动。
2. **弹簧锚点在轮子上方 100px，自然长度 100px** —— 所以"名义位置"处弹簧正好不受力，任何压缩/拉伸都产生回复力。
3. **滑槽允许轮子自由转动** —— 这是车轮能滚起来的前提。⚠️ 见 §9 踩坑 1。

### 移植映射表

| 原版（Nape） | planck.js / Box2D | matter.js | Rapier 2D |
|---|---|---|---|
| `GrooveJoint` + `SpringJoint` | **`WheelJoint`**（官方定义即 "point to line constraint with rotational motor and linear spring/damper"） | `Constraint` + `Spring`，或自写 | `PrismaticJoint` **需另开旋转**，推荐自写/组合 |
| 车轮扭矩（直接 `applyTorque`） | `wheelBody.applyTorque(t)` | `Body.setAngularVelocity` / `applyForce` 偏心 | `RigidBody.applyTorque` |
| 车轮角阻尼切换 | `setAngularDamping` | `frictionAir` | `setAngularDamping` |
| 车身线性阻尼 | `setLinearDamping` | `frictionAir` | `setLinearDamping` |
| 车身扭矩（调姿） | `chassis.applyTorque(t)` | `Body.torque` | `applyTorque` |
| 氮气推力 | `chassis.applyForce(f, worldPoint)` | `applyForce(pos, f)` | `addForceAtPoint` |

### 弹簧参数换算（Nape → Box2D）

Nape 用「刚度 k / 阻尼 c」，Box2D 用「频率 f / 阻尼比 ζ」：

```
ω  = sqrt(k / m_eff)          f  = ω / (2π)
ζ  = c / (2 * sqrt(k * m_eff))
```

`m_eff` 取约束两端沿轴向的**约化质量**（轮子占主导，车身重得多）。`src/planckAdapter.js` 的 `springParams()` 就是这么算的。**这是一个近似**：两个引擎对弹簧的数值积分方式不同，落地后仍需要按手感微调 `frequencyHz`。

- **620 个 `<entity>` → 1167 个实例**；世界宽 **60000 px**、高 3000 px。
- `positions` 是逗号分隔的 `"x y"` 对，一对就是一个实例。
- `rotation` 单位是**弧度**。
- 地形**不是分块瓦片**：9 段 `t2` 各持一段 Catmull-Rom 控制折线，按切线转角递归细分（`splineTreshold=0.95`），首尾下移 400px 封口，最终合成**一个静态多边形**。
- `tileSize` 是死元数据（运行时从不读取）。
- 视差：`layer ≤ 70` 滚动 `(0.5, 0)`（天空垂直不动）、`71–75 → (0.7,0.7)`、`≥ 76 → (1,1)`。
- 相机：`x = Lerp(car.x + 100, heli.x, heliFactor)`，`y = car.y + clamp((射线地面Y − car.y)*0.5 − 100, 上限 230)`，垂直加速度上限 70 px/s²，死区 3px。
- 胜负：**胜** = `car.x >= goal.x`；**负** = 低速（`v.x<0`，或 `v.x<30 && |v.y|<100`）持续 2 秒，或油氮耗尽时 1.5 秒。**没有血量、没有撞车失败。**
- 计分：`Fail()` 给 `money += int(d*d*4)`，`d = maxCarX * 0.001`。全程 **3127 ft**，`DistanceToFeet(x) = x*3127/(goal.x − spawner.x)`，分母 50050.198 px ⇒ 16.0058 px/ft。
- ⚠️ **本 SWF 里 `StuntManager` 是死代码**：`Update()` / `GetAchievementTextAndMoney()` / `ShowStuntText()` 从未被调用，`m_stuntMoney` 恒为 0。它定义了连击（StriKe $50/150/300/1000、Breach $3000/6000/30000/50000、连击 ×7）但**完全不生效**。**原版没有任何空翻/滞空/翻滚判定。**

## 7.5 碰撞与伤害模型（僵尸 / 障碍 / 武器）

### 碰撞类别位

`ZombyHillCommon/CollisionMask.as:6-14`：

```as3
LANDSCAPE = 1,  CAR = 2,  ZOMBIE = 4,  BOX = 8,  BROKENBOX = 16
```

**车身和每个车轮的类别完全相同**：`CAR | BOX | LANDSCAPE | ZOMBIE = 15`
（`CarBehaviour.as:195-226` 底盘、`:332-362` 车轮）。这是一个"我同时是车、箱子、地形和僵尸"的粗暴写法，目的是确保和一切相撞。

> 因此**车身与自己的车轮互不碰撞，绝不是靠类别实现的**，而是靠关节：Nape 的 `Constraint.ignore` 默认为 `true`，等价于 Box2D 的 `collideConnected: false`。（`SetCollisionGroup(param1, param2)` 在 `PhysicalShapeNape.as:45-85` 里实际写的是 `group = param1; sensor = param2;` —— 第二个参数是 **sensor 掩码**，这一点反编译可读，但 `sensor` 与碰撞响应的确切交互**属于未知**，不要据此推断。）

| 对象 | 类别 | 掩码 | 说明 |
|---|---|---|---|
| 地形 `t2` | 默认(1) | `-1` | `Embeds_Templates_xml.as:30` |
| 车身 / 车轮 | 15 | — | `collideConnected:false` 负责轮-身互斥 |
| 木箱 `boxt` | 8 | 31 | `Embeds_Templates_xml.as:613` |
| 碎片 `BrokenBox` | 16 | 1 | 只与地形交互 |
| 行走僵尸 | group `0`, ignore-mask `0xFFFFFFFF` | — | **纯传感器，永不阻挡** |
| 飞行布娃娃（完好） | 4 | 3（CAR\|LANDSCAPE） | 会与车撞 |
| 飞行布娃娃（被枪击/超时后） | 4 | 1（仅 LANDSCAPE） | **不再与车交互** |

### 僵尸

| | 普通 | 大型 |
|---|---|---|
| 模板 | `WalkingZombie` / `i6` | `big_WalkingZombie` |
| 传感器矩形 | `rect="-20 -35 20 50"` → **40 × 85 px** | 同结构 |
| 血量 `life` | **3** | — |
| 移动 | `GlideBehaviour`，向左 **−40 px/s**，再用射线吸附到地形 | — |
| 死亡生成 | `FlyingZombieBehaviour`，`breakForce=25000`、`density=5`、`ragdollResource="Zombie1"` | `breakForce=130000`、`density=30`、`"Zombie_v3_r"` |

大型僵尸是 **30/5 = 6 倍密度**、**130000/25000 = 5.2 倍关节断裂力**。

**行走僵尸是传感器 —— 车不会撞到它，只是穿过时触发 `OnCarCollided` 把它变成布娃娃。** 真正会挡路的是死亡后生成的布娃娃刚体（完好时才与车碰撞）。

布娃娃 = 11–12 个具名段 + 10 个转动关节（角度制，例如 `torso-head −15..15`、`upperarm-forearm 0..160`）。关节在**约束冲量超过该关节的 `breakForce`** 时断裂；0.5 秒内断裂会派发 `ZombieBlowEvent("zb", 断裂数)`。

### 伤害 / 击杀

`CarWeaponBehaviour`（`CarWeaponBehaviour.as:53-70` 默认值 / `Embeds_Templates_xml.as:22,103,114` 模板覆盖）：

| 参数 | 默认 | Car1/Car2/Car3 模板 |
|---|---|---|
| `damage` | 1 | **1.5** |
| `bulletCount` | 7 | **20** |
| `reloadTime` | 0.3 | **0.75** |
| `minDistance` / `maxDistance` | 50 / 400 | — |

开火消耗 1 发子弹、重置 `reloadTimer`，并向目标发送 `DamageMessage(damage)`。

> **净效果：`life = 3` ÷ `damage = 1.5` ⇒ 两枪打死一只行走僵尸。**
> 载具与僵尸的"撞击"**不扣任何血** —— 见下。

### 障碍

木箱 `boxt`：`breakImpulse = 700`（内部默认 500，被模板覆盖），当 Nape 仲裁器的 `totalImpulse().length() > 700` 时碎裂成 `BrokenBox`。

### ⚠️ 「伤害模型」的关键否定结论

**车本身完全没有血量。** `CarBehaviour` 里只有 `m_fuel`、`m_boost`、`m_stalled`、`m_wheelsBlocked`、`m_brakeForced`，**没有 `life` / `health` 字段**。

原版**不存在**撞车失败、翻车失败、爆头失败、出界失败、超时失败。撞击唯一的效果是：
1. 把撞到的行走僵尸变成布娃娃（撞得越狠飞得越远）
2. `OnCollide` 播放一声惨叫，音量参数取 `arbiter.totalImpulse().length()`
3. 累积 `maxCarX`，用于结算里程

唯一的失败路径是"**停下来**"：低速（`v.x<0`，或 `v.x<30 && |v.y|<100`）持续 2 秒，或油氮耗尽时 1.5 秒。

> 这意味着：如果主人想在自己的游戏里加"撞击掉血 / 血量归零重来"，那是**你自己的设计选择，不是原版行为** —— 请把它和上面的观察到的原版行为分开标注。

## 9. 踩坑记录（移植时一定会遇到，血泪）

这三个坑我都真踩过，每个都表现为"车完全不动"，原因却完全不同：

### 坑 1：用 `PrismaticJoint` 实现滑槽 → 车轮转不了
Nape 的 `GrooveJoint` 只约束锚点落在一条线上，**相对转动自由**。Box2D 的 `PrismaticJoint` **同时锁死相对转动**，所以车轮物理上无法旋转 —— 现象是加 2500 扭矩车身纹丝不动、轮子转速恒为 0。
✅ **正确做法：用 `WheelJoint`**（planck 官方定义："a point to line constraint with a rotational motor and a linear spring/damper"），它就是 `GrooveJoint + SpringJoint` 的合体。

### 坑 2：碰撞类别自己加戏 → 车轮不与地面碰撞（**是人家自己造的坑，不是原版的**）
这是坑 1 的**错误后续**，记在这里是因为它很容易重演：
当时把"车轮不转"误诊成"车身与车轮穿了碰撞过滤器"，于是给两者分配了互斥类别 `0x0001 / 0x0002`。结果**地面用的是默认类别 `0x0001`**，而车轮 mask 恰好把它排除掉了 —— `catGround & maskWheel == 0`，**车轮从此不与地面碰撞**，现象变成"轮子悬空狂转、车身用肚子擦地滑行"。

✅ **正确结论（已实测）**：`collideConnected: false` **单独就完全够用**，不需要任何自定义类别。
`tools/collision-test.mjs` 的对照数据：

| 碰撞类别方案 | `collideConnected` | 3 秒后速度 | 轮转速 |
|---|---|---|---|
| 默认类别 | `false` | **491 px/s** | 47.12 |
| **原版类别集** `CAR\|BOX\|LANDSCAPE\|ZOMBIE` | `false` | **491 px/s** | 47.12 |
| 互斥类别 | `false` | 491 px/s | 47.12 |
| 默认类别 | `true` | **0** | 0 ❌ |
| 原版类别集 | `true` | **0** | 0 ❌ |
| 互斥类别 | `true` | 491 px/s | 47.12 |

看得很清楚：**只要 `collideConnected: false`，用什么类别都一样能跑**；而一旦设成 `true`，只有互斥类别能"绕过去"——那是掩盖问题，不是解决问题。

而且**原版给车身和车轮的碰撞类别是完全相同的**（见 §7.5），所以它根本不可能靠类别来隔离自己的车轮。

`planckAdapter.js` 现在默认使用**原版真实的类别集**；互斥方案降级为 `opts.isolateWheels = true`，仅在"移植到某个引擎、且该引擎的关节连接体排除不可信"时才作为保险启用。

### 坑 3：车轮锚点太高 → 车身压在地上
把轮轴放在底盘多边形最低点上时，悬挂静态下沉（≈ 车重 / 2k）会把车身拉到贴地，摩擦直接吃掉驱动力。现象是车能勉强挪动但极慢。
✅ **正确做法：轮轴放在「底盘最低点 + 轮半径」处**，离地间隙 ≈ `2r − 下沉`。
（另外别把车从几百像素高砸下来：落地冲击会把悬挂压到底，一旦底盘接了地就再也起不来。）

## 11. 快速上手

import * as planck from 'planck';
import { createPlanckCar } from './src/planckAdapter.js';

const car = createPlanckCar(planck, VEHICLES.Car1, {

addEventListener('keyup',   (e) => input.onKey(e.keyCode, false));

  car.step(input.intent(), DT);   // 先算驾驶，再步进物理

  requestAnimationFrame(frame);
}
frame();
